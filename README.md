# QA Automation: ตรวจคำขอลงทะเบียนเครื่องอัตโนมัติ

> **สรุปสั้นๆ:** เมื่อสาขาขายมือถือแบบผ่อนแล้วส่งเรื่องขอลงทะเบียนเครื่องเข้ามา
> โปรแกรมนี้จะเปิดระบบที่เกี่ยวข้อง 5 ระบบแทนคน เช็กว่าข้อมูลตรงกันทุกที่
> แล้วบันทึกผลว่า "ผ่าน" หรือ "ไม่ผ่าน เพราะอะไร" ให้เจ้าหน้าที่ดู

## ที่มา

บริษัทขายมือถือแบบผ่อน เครื่องที่ขายแบบผ่อนทุกเครื่องต้องลงทะเบียนเข้า **MDM**
(ระบบจัดการอุปกรณ์ ใช้ล็อกเครื่องได้ถ้าลูกค้าไม่ผ่อนต่อ) หลังสาขาส่งมอบเครื่องให้ลูกค้า
สาขาจะส่งเรื่องเข้ามาขอให้ยืนยันการลงทะเบียน

ก่อนยืนยัน เจ้าหน้าที่ต้องเช็กว่าเครื่องที่ส่งมอบตรงกับที่ลูกค้าขอผ่อนจริง
โดยเปิดดูข้อมูลจากหลายระบบ:

| ระบบ | ใช้ดูอะไร |
|---|---|
| **7Chat** | ช่องทางที่สาขาส่งเรื่องเข้ามา |
| **CRM** | รายละเอียดเรื่องที่ส่งมา: ชื่อลูกค้า สาขา เลขใบสมัคร เลขเครื่อง |
| **iLoan (ITOS)** | ใบสมัครขอผ่อน: รุ่น ความจุ สี ราคา เงินดาวน์ |
| **ITEC** | บิลขายจริงที่หน้าร้านเปิด (โปรแกรมบน Windows) |
| **MDM** | เครื่องลงทะเบียนเข้าระบบครบแล้วหรือยัง |

เรื่องหนึ่งต้องเทียบชื่อลูกค้า สาขา ราคา รุ่น และเลขเครื่อง (Serial/IMEI) ข้ามทุกระบบ
ทำมือทีละเรื่องทั้งช้าและพลาดง่าย

## โปรแกรมนี้ทำอะไรแทนคน

```
 ① รอเรื่องใหม่ใน 7Chat แล้วเปิดเรื่องนั้นใน CRM
            │
            ▼
 ② เอาเลขใบสมัครไปค้นใน iLoan, ค้นบิลใน ITEC, ค้นเครื่องใน MDM
            │
            ▼
 ③ ตรวจทุกช่องว่าตรงกันทุกระบบไหม
            │
      ┌─────┴──────┐
   ตรงครบ        มีจุดไม่ตรง
      │              │
      ▼              ▼
 บันทึกว่า "ผ่าน"    บันทึกว่า "ไม่ผ่าน" พร้อมบอกว่าไม่ตรงที่ช่องไหน
 (ถ้าเปิดโหมดอัตโนมัติ:
  ยืนยันลงทะเบียน + ตอบสาขา + ปิดเรื่องให้เลย)
```

ผลทั้งหมดถูกบันทึกลง Google Sheets แยกเป็น iPhone / Android / ไม่ผ่าน
เจ้าหน้าที่จึงเปิดดูได้ทันทีว่าเรื่องไหนต้องตามต่อ

## ความท้าทาย และวิธีแก้

**1. ต้องปลอดภัยไว้ก่อน**
การยืนยันลงทะเบียนและการปิดเรื่องเป็นการแก้ข้อมูลจริงที่ย้อนกลับยาก
จึง **ปิดโหมดอัตโนมัติไว้เป็นค่าเริ่มต้น** ต้องสั่งเปิดเองถึงจะทำ
และจะตอบกลับสาขาก็ต่อเมื่อการลงทะเบียนสำเร็จจริงเท่านั้น

**2. ข้อมูลจริงไม่เรียบร้อยเสมอไป**
ข้อมูลที่เจอจริงมีหลายแบบ เช่น ช่องเลขเครื่องที่มีเลขผิดประเภทหรือลิงก์เว็บปนมา,
เลขเครื่อง iPhone ที่มีตัวอักษรเกินมาข้างหน้า, รหัสสาขาที่แต่ละระบบเขียนไม่เหมือนกัน
และชื่อสาขาที่สะกดต่างกันเล็กน้อย โปรแกรมต้องจัดรูปแบบข้อมูลพวกนี้ให้เหมือนกันก่อนเทียบ

**3. ถ้าหาไม่เจอ ให้ลองทางอื่นก่อน**
ถ้าหาเครื่องใน MDM ด้วยเลขเครื่องไม่เจอ จะลองหาจากรายการเครื่องของสาขานั้น
ถ้ายังไม่เจอ จะเช็กกับบันทึกคำขออนุมัติพิเศษ และถ้าเลขเครื่องไม่มีในระบบเลย
จะเปิดไฟล์สัญญา PDF แล้วอ่านเลขจากภาพด้วย OCR (การอ่านตัวอักษรจากรูป)

**4. เลิกพึ่งการกดหน้าจอเท่าที่ทำได้**
เวอร์ชันแรกเปิดเบราว์เซอร์แล้ววางข้อมูลลง Google Sheets เหมือนคนทำ
แต่ถ้าหน้าตาเว็บเปลี่ยนนิดเดียวก็พัง จึงเปลี่ยนมาเขียนผ่าน Google Sheets API แทน
ทำให้เร็วขึ้นและเสถียรกว่าเดิม

## สำหรับนักพัฒนา

**เทคโนโลยีที่ใช้:** Python · Playwright (ควบคุมเว็บ) · pywinauto (ควบคุมโปรแกรม Windows) ·
gspread (Google Sheets API) · PyMuPDF + Tesseract (OCR) · openpyxl

### โครงสร้างโปรเจกต์

```
main.py                 ควบคุมลำดับการทำงานทั้งหมด
qa_automation/
  sevenchat.py          รอเรื่องใหม่ใน 7Chat (อ่านอย่างเดียว)
  crm.py                อ่านรายละเอียดเรื่องจาก CRM
  iloan.py              ค้นใบสมัคร / ยืนยันลงทะเบียนใน iLoan
  itec_desktop.py       ค้นบิลในโปรแกรม ITEC
  mdm.py, mdm_sheet.py  เช็กเครื่องใน MDM + ทางสำรองจากรายการเครื่องของสาขา
  cmc_summary.py        ทางสำรองจากบันทึกคำขออนุมัติพิเศษ
  rules.py              กฎการตรวจว่าข้อมูลตรงกันทุกระบบ
  sheet_writer.py       เขียนผลลง Google Sheets และไฟล์ Excel ในเครื่อง
  sheet_reader.py       อ่านชีทต้นทางผ่าน service account (ชีทตั้งเป็น "จำกัด" ได้)
  models.py, config.py  โครงสร้างข้อมูล / อ่านค่าตั้งค่าจาก .env
```

### วิธีรัน (Windows)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\playwright.exe install chromium
copy .env.example .env      # กรอก URL ของแต่ละระบบ, user/password และ Sheet ID

# ตรวจเรื่องที่ระบุเลข
.\.venv\Scripts\python.exe main.py --case-id <เลขเรื่อง> --headed

# รอเรื่องใหม่จาก 7Chat แล้วตรวจต่อกัน 10 เรื่อง
.\.venv\Scripts\python.exe main.py --wait-7chat --limit 10 --headed
```

ถ้ายังไม่ได้ตั้งค่า Google Sheets โปรแกรมจะบันทึกผลลง `output/qa_report.xlsx` ในเครื่องแทน

<details>
<summary>ตั้งค่า Google Sheets API (ทำครั้งเดียว)</summary>

1. ใน [Google Cloud Console](https://console.cloud.google.com/) เปิดใช้ **Google Sheets API**
2. สร้าง **Service Account** (บัญชีสำหรับโปรแกรม) แล้วสร้าง key แบบ JSON
3. เก็บไฟล์ไว้ที่ `credentials/service_account.json` (ไฟล์นี้ไม่ถูกอัปขึ้น git) แล้วตั้งค่าใน `.env`:
   `GOOGLE_SERVICE_ACCOUNT_FILE=./credentials/service_account.json`
4. แชร์ชีทให้ email ของ service account (`xxx@your-project.iam.gserviceaccount.com`):
   ชีทที่บันทึกผลให้เป็น **ผู้แก้ไข** ส่วนชีท MDM Branch และ CMC Summary ที่อ่านอย่างเดียวให้เป็น **ผู้มีสิทธิ์อ่าน**
5. ชีททุกอันตั้ง "การเข้าถึงทั่วไป" เป็น **จำกัด** ได้เลย เพราะโปรแกรมอ่าน/เขียนผ่าน service account
   ไม่ต้องเปิดแบบ "ทุกคนที่มีลิงก์"

</details>
